# CameraNativeBridge

Cross-compiled [libgphoto2](https://github.com/gphoto/libgphoto2) +
[libusb‑1.0](https://github.com/libusb/libusb) for Android, with a robust JNI
bridge and a Kotlin facade, packaged as an Android library module (`.aar`).

**Target camera:** Canon EOS M50 Mark II (PTP — served by the `ptp2` camlib).

## Vendor sources

The sources live in `camerabridge/src/main/cpp/vendor/`:

```
camerabridge/src/main/cpp/vendor/
├── libgphoto2/     # full gphoto2 tree (libgphoto2_port is inside it)
└── libusb/         # full libusb-1.0 tree (v1.0.27 — needs
                    # libusb_wrap_sys_device, present since 1.0.23)
```

Fetch/refresh with:

```bash
scripts/fetch-sources.sh
# or use existing checkouts:
LIBGPHOTO2_SRC=/path/to/libgphoto2 LIBUSB_SRC=/path/to/libusb scripts/fetch-sources.sh
```

(or register them as `git submodule add …` of this repo.)

Build the AAR:

```bash
./gradlew :camerabridge:assembleRelease
# -> camerabridge/build/outputs/aar/camerabridge-release.aar
```

## What ships inside the AAR

| library                | role                                                   |
|------------------------|--------------------------------------------------------|
| `libcamera_bridge.so`  | JNI layer (what Kotlin loads)                          |
| `libgphoto2.so`        | gphoto2 core                                           |
| `libgphoto2_port.so`   | port core (contains our libltdl *shim*)                |
| `libusb1.so`           | the libusb-1.0 iolib — **dlopen()-ed at runtime**      |
| `libptp2.so`           | the PTP camlib — **dlopen()-ed at runtime**            |
| libusb core            | static, linked into the two above                       |

The dynamic iolib/camlib are loaded through a tiny `dlopen()`-based
`libltdl` shim (`cpp/ltdl/`), pointed at the app's `nativeLibraryDir` via
libgphoto2's own `IOLIBS` / `CAMLIBS` env-var support.

## The Android USB fd workaround (no root, no kernel detach)

Android's `UsbManager` owns USB discovery and permissions. This build wires
libphoto2's **upstream native support** for that model (nothing is patched):

1. Kotlin opens the device: `usbManager.openDevice(device)` →
   `connection.fileDescriptor` (an int fd).
2. `NativeCameraInterface.init(connection)` hands the fd to
   `nativeInitWithFd(fd, nativeLibDir)`.
3. The C layer calls **`gp_port_usb_set_sys_device(fd)` *before* any port/camlib
   load** (this ordering is mandatory — see `camera_bridge.cpp`).
4. The `usb1` iolib then runs
   `libusb_set_option(ctx, LIBUSB_OPTION_NO_DEVICE_DISCOVERY, NULL)` +
   `libusb_wrap_sys_device(ctx, fd, &handle)` (libusb ≥ 1.0.23), so libgphoto2
   enumerates exactly the wrapped device — no `/dev/bus/usb` scanning ever
   happens.

Enabled by `HAVE_LIBUSB_WRAP_SYS_DEVICE` /
`HAVE_LIBUSB_OPTION_NO_DEVICE_DISCOVERY` in `cpp/config/config.h`.

Configuration is a **hand-written** `config.h` replacing the one normally
generated by configure/meson (Android stdlib notes inline); a matching
`gphoto2-endian.h` for little-endian ARM is in `cpp/config/libgphoto2/`.

## Public API (Kotlin)

`com.mav.cameranativebridge.NativeCameraInterface`

```kotlin
val iface = NativeCameraInterface(context)

val connection = usbManager.openDevice(device)!!   // permission already granted
iface.init(connection)

iface.libraryVersion()                              // "libgphoto2 2.5.31 …"

// live view — JPEG/MJPEG frame bytes from capture_preview
val frame: ByteArray = iface.capturePreviewOnce()
iface.previewFlow().collect { frame -> paint(frame) }

// files
val files: Array<String> = iface.listFiles()        // "<folder><path>…"
iface.downloadFileTo("/store_00010001/DCIM/100CANON/",
                     "IMG_0001.JPG", File(cacheDir, "IMG_0001.JPG"))

iface.close()
```

Downloads stream via `gp_camera_file_read()` in ~256 KiB chunks and are written
directly to the caller's `ParcelFileDescriptor` fd — a 200 MB `.CR3` file never
materializes as one heap allocation.

## Notes / gotchas

* **Order matters:** always `init()` before preview/file APIs, and don't call
  file APIs from multiple threads — all native calls serialize behind one mutex.
* EOS live view must be started by the *camera app's* own PTP calls: the
  `ptp2` camlib starts it inside `gp_camera_capture_preview` automatically.
* USB permission UX (`requestPermission`) is an app-layer concern; unless it
  is granted, `openDevice()` returns null and `init()` throws.
* To support other cameras later, add more camlibs to CMake target `ptp2`'s
  pattern (`camlibs/canon`, …) and widen `chooseAbilities()` in
  `camera_bridge.cpp`.

## Layout

```
CameraNativeBridge/
├── settings.gradle.kts / build.gradle.kts / gradle.properties
├── scripts/fetch-sources.sh
└── camerabridge/                         # Android library module
    ├── build.gradle.kts                  # AGP 8, CMake, arm64-v8a + armeabi-v7a
    ├── consumer-rules.pro
    └── src/main/
        ├── AndroidManifest.xml
        ├── kotlin/…/NativeCameraInterface.kt
        └── cpp/
            ├── CMakeLists.txt            # master build (links everything)
            ├── camera_bridge.cpp         # the JNI bridge
            ├── config/config.h           # Android config, fd workarounds
            ├── config/libgphoto2/gphoto2-endian.h
            ├── ltdl/{ltdl.h,ltdl.c}     # libltdl shim over dlopen()
            └── vendor/{libgphoto2,libusb}/   # via fetch-sources.sh
```

## Sanity check on a host toolchain (no NDK needed)

`CMakeLists.txt` also configures/purely compiles the C layers on a plain Linux
host (`ninja ltdl usb1_static gphoto2_port usb1 gphoto2 ptp2`) — a convenient
smoke test for source/config drift; the JNI target is Android-only.
